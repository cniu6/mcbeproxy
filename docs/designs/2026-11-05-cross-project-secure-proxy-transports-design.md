# go_web / mcbeproxy 双线路安全代理设计

状态：设计与逐文件计划已获批准，双项目 HY2 / Mieru TCP 入口、出口和管理接线已实现并完成本地互操作；尚未部署或完成真实 ET / MCBE 验收。本稿替代此前 SS2022 / HY2 / Trojan 三协议候选设计。
范围：两个项目均提供 HY2 主力线路、Mieru TCP 兼容线路的入口与出口，保留已有 SOCKS5 和其他出站。
实施边界：允许修改产品代码和锁定依赖；不修改真实配置、端口映射或服务，不部署、不重启、不提交。

## 1. 最新需求与推荐结论

用户需要的不是只支持 TCP 的单一方案，而是两条分工明确的线路：

1. **网络允许 TCP、UDP：默认推荐 HY2/QUIC 主力。** 同时代理业务 TCP 和业务 UDP；游戏 UDP 使用不可靠数据报，不为了外层可靠交付等待丢失的旧报文。
2. **两程序间不允许 UDP：使用 Mieru TCP 兼容线路。** 两程序间只连接 TCP 端口，业务 TCP、UDP 都能转发，不需要用户申请域名或管理 TLS 证书。

“默认”指新建安全代理配置时的推荐，不自动迁移、替换或重启已有 SOCKS5/ET/其他节点。

### 必须区分三层

| 层级 | HY2 主力 | Mieru TCP 备选 |
| --- | --- | --- |
| 应用需要代理的业务 | TCP、UDP 均支持 | TCP、UDP 均支持 |
| 两程序之间的外层网络 | UDP 上的 QUIC | TCP 上的 Mieru 加密流 |
| 业务 UDP 的交付方式 | QUIC 不可靠数据报 | 在可靠有序流内保留 UDP 报文边界 |
| 服务端最终连接目标 | 按请求发送 TCP 或 UDP，可经 ET | 按请求发送 TCP 或 UDP，可经 ET |
| 新入口监听 | 一个 UDP 端口 | 一个 TCP 端口 |

HY2 不是“只能代理 UDP”：它的外层用 UDP，但可以同时代理 TCP/UDP 业务。网络有 TCP+UDP 不等于主力必须同时建立一条 TCP 控制连接和一条 UDP 连接；这里不设计这种双通道私有协议。

本设计不把业务 TCP/UDP 与外层 TCP/UDP 混称，也不保证任何一种协议在所有线路上延迟最低。

## 2. 重新比较后的取舍

### 为什么主力推荐 HY2

- 官方协议明确：业务 TCP 使用独立 QUIC 流；业务 UDP 必须使用 QUIC 的不可靠数据报，不把游戏报文强制改成可靠有序字节流。
- 相比纯 TCP 包装 UDP，某个游戏数据报丢失不要求等待外层 TCP 重传后才能交付后续数据报。游戏自身需要的可靠性仍由 RakNet/应用处理。
- 客户端复用官方 Go core；服务端经专项批准使用 sing-quic，将认证用户放入 handler context 后直接适配 ET/现有出口。官方 core 服务端的共享 Outbound 不携带用户，不能满足每用户路由与禁 UDP 权限。
- 每入口一个明确 UDP 端口，无普通 SOCKS5 UDP ASSOCIATE 的客户端可见随机中继端口或 BND 私网地址通告。
- 证书仍是协议必需品，但由产品自动生成、持久化、导出可信身份；用户不必注册域名、部署网站或申请公有 CA 证书，详见第 5 节。

HY2 的代价是 QUIC/加密/拥塞控制与分片开销；同一 QUIC 连接的业务还共享拥塞控制和部分资源，不能声称“UDP 丢包完全不影响其他流”。是否适合作为该机器的低延迟主力，必须以同路由 p95/抖动和资源占用验收。

### 为什么不直接用 Mieru UDP 作低延迟主力

Mieru 支持外层 TCP 和 UDP，但当前核对的 Go 客户端对业务 UDP 使用 PacketOverStream；其 UDP 传输实现也维护顺序、确认与重传。**外层叫 UDP 不等于业务 UDP 已变成独立不可靠数据报。**

因此不能仅因同一协议可选 TCP/UDP，就承诺它比 HY2 数据报更适合 MCBE。Mieru TCP 保留为无 UDP 网络的兼容线路，不把 Mieru UDP 设为本稿默认。

### 其他候选的处理

- TUIC：也是合理的 QUIC 候选，支持 UDP 数据报/其他 relay 模式；同样需要服务身份信任。当前没有同环境基准证明其优于 HY2，首期不再增加一套 QUIC 服务端和参数。
- SS2022：原生加密 UDP 是合理性能基线，但用户不选择它作为本次主力；本设计不恢复其首期新增范围，也不改已有节点。
- VMess/mKCP：外层 UDP 上的可靠流，不视作不可靠游戏数据报捷径；存在具体版本参数兼容成本，首期不加。
- Trojan/AnyTLS：可承载 UDP over TCP，但不满足本次降低证书运维负担的主要取舍，首期由 Mieru TCP 覆盖。
- GOST Relay：接近 SOCKS 的转发模型，但本身无加密；公网需要另加安全传输，不作为默认安全入口。
- 自定义协议：不自行实现安全握手、密码学、QUIC、ARQ 或兼容线格式；只写成熟协议库与现有路由之间的适配层。

若用户坚持完全不能存在任何证书（包括程序自动管理），HY2 不满足该额外约束，必须重新取舍；不能以关闭服务端验证掩盖矛盾。

## 3. 两项目角色与既有能力

### go_web

- `internal/tunnel/engine.go` 已有 `Dial(ctx, addr)`、`ListenPacket(ctx)`、`Close()`；复用这一出口合同，不新建第二套目标转发器。
- `internal/tunnel/manager.go` 已有账户 ET 会话租约；新入口引用账户，不能重复取得另一套账户授权或误关其他消费者的 ET 会话。
- 保留账户既有 SOCKS5 Bind/Port/Username/Password 和 ET 配置，新增独立安全代理入口集合，以及 HY2/Mieru 上游参数。
- 现有 UDP 地址族修复和 ET 局部故障隔离保留，不把本设计当作它们已经部署的证明。

### mcbeproxy

- 复用 `internal/proxy/proxy_ports.go`、`internal/config/proxy_port.go` 的入口生命周期、来源权限和目标路由。
- HY2 出站已有接线；Mieru 出站可经已锁定 Mihomo 适配。已有客户端不等于服务端入口或所有代理链组合已经完成。
- 协议、外层传输与内核选择分开保存；不因为新入口上线而静默切换旧节点的 native/Mihomo 路径。
- go_web 也必须能作为两种协议的客户端，mcbeproxy 也必须能作为两种协议的服务端，不只实现单向组合。

## 4. 实际数据流、端口和网络约束

主力示例：

`游戏客户端 → mcbeproxy 游戏监听 → HY2 客户端 → UDP/QUIC → go_web HY2 入口 → 账户 ET Engine → 目标服`

备选示例：

`游戏客户端 → mcbeproxy 游戏监听 → Mieru TCP 客户端 → TCP → go_web Mieru 入口 → 账户 ET Engine → 目标服`

角色互换：

`应用/固定转发 → go_web HY2 或 Mieru 上游 → mcbeproxy 对应入口 → 已选出口/代理链 → 目标`

- HY2 使用管理员指定的单个 UDP 端口；Mieru TCP 使用管理员指定的单个 TCP 端口。可配置成同一数字的不同传输，也可不同数字，均明确标注，不猜协议、不挤占原 SOCKS 端口。
- 只开放两程序之间的 TCP 时，Mieru 可以把业务 UDP 搬到服务端；但最终出口仍必须能向目标发送 UDP。
- 若 go_web 的 ET 引擎本身要经 UDP 连接 ET 节点，整台主机完全没有可用 UDP 出站时，Mieru TCP 入口不能使该 ET 后段凭空可用。需改用有 UDP 能力的远端出口，或调整明确允许的上游。
- NAT/容器的入口映射不能靠证书或密码生成：仍需暴露所选的固定端口，但不要求随机 SOCKS UDP 范围。
- IPv4/IPv6 按实际监听族处理，不将 `::` 传给 `udp4`；目标族若不受所选 ET/上游支持，明确拒绝，不回退直连。
- 解密认证后直接接现有 Engine/路由，不绕本机 SOCKS；新建流固定已选出口，健康探测只影响未来连接。
- 明确拒绝路由循环和不具备外层承载能力的代理链。HY2 的底层 PacketConn 已接入所选前一跳的 UDP 转发；Mieru 等 Mihomo 适配通过实例级拨号器注入前跳，不注册全局代理名，不偷偷从本机直发。
- 后跳 HY2 无论承载业务 TCP 还是 UDP，都要求前跳能代理 UDP；前跳本身可以是 HY2、SOCKS5 或 Mieru TCP 等，不要求把所有节点改成 HY2。Mieru TCP 可先将后跳 HY2 的 UDP 报文封装进 TCP，但仍有 TCP 队头阻塞；前跳服务器至后跳 HY2 仍需 UDP 可达。

## 5. HY2 身份和密码：自动管理，不要求用户手工办证书

### 初次创建

用户创建 HY2 入口时，程序生成并持久化独立 TLS 私钥和自签服务证书，使用标准 Go 加密库及加密随机数；同时生成强认证密码。只有明确创建操作才写入，不在页面读取、测速或每次重启时重新生成。

自动生成身份使用稳定的逻辑服务名/SAN，与公网 IP 解耦。连接配置分别保存真实拨号 IP:端口和验证服务名；管理员自备合法证书仍可作为高级选项。

界面提供“一键生成连接配置/导入”，包含入口地址、服务名、可信证书或固定身份摘要及认证参数。私钥只留服务端，不进入导出。用户仍需确认客户端实际可达的入口地址，不能把 ET 出口 IP 或容器私网地址自动当成公网入口。

### 客户端信任

- 本产品两端默认通过管理员可信导入的服务证书建立专用信任池，并校验服务名、有效期和证书；可同时校验固定的 SHA-256 身份摘要。
- 不信任首次握手中对方随意发来的自签证书，不静默 TOFU，不因为密码正确就省略服务端身份验证。
- 若选用第三方客户端的指纹固定模式，需核对该客户端到底固定证书还是公钥、是否仍验证有效期等语义；不得把内部导出格式冒充任意第三方可直接导入。
- 不以无人校验的 `insecure=true` 作为简化部署方案。必要的库级自定义验证必须完成等价的明确校验并有负例测试。
- 导出/导入经已认证管理渠道或可信离线操作完成；指纹与密码都是配置的一部分，不自动通过未验证网络获取信任。

### 重启、过期和轮换

正常重启复用原身份，不能导致所有客户端指纹失配。界面显示证书到期与信任状态，支持管理员显式轮换；信任更新通过同一可信导入过程完成，不自动信任陌生新证书。

临近过期给出预警；证书已过期或信任不匹配时，新握手明确失败。不得为避免失败而跳过验证，也不承诺跨证书/密钥轮换迁移存量连接。

本稿自动管理的是私有部署证书，不依赖 ACME、公有 CA、域名注册或外部公网 IP 检测服务。

## 6. Mieru TCP 备选与安全合同

- 外层限定 TCP，界面明确标注“业务 UDP over TCP”；服务地址可以是 IP，不要求 TLS、域名或用户维护证书。
- 复用官方加密、用户认证、时间窗口与重放处理，用户名和密码不能为空；默认生成高强度随机密码，不自行替换派生算法。
- 使用锁定 Go API 的 `DialContext`、`server.Accept` 和 PacketOverStream/UDPAssociate 适配；服务端必须完成相应协议应答与 UDP 帧处理后接入现有 Engine。
- 不在两程序间回退成普通 SOCKS5 UDP ASSOCIATE，不另建客户端可见的随机 UDP 入口。
- 核对时钟偏差影响，认证/时间失败明确分层提示；不承诺凭据派生方案具有未经规范确认的前向保密属性。
- 使用保守、可控的复用策略，不默认把所有玩家共享到单条 TCP 连接；即使每关联独立 TCP，也不能消除关联内部的队头阻塞。
- Mieru TCP 备选以“受限网络可用”为目标，不以它的吞吐或协议作者的概括速度描述替代游戏 p95 延迟基准。

### 两条线路共同要求

认证前不创建目标连接/新 ET 业务流；ET 已有的账户后台授权不等于客户端转发许可。拒绝空密码，包括回环接入，不继承旧 SOCKS 的回环免密例外。

密码、TLS 私钥、完整认证报文不进日志、公开状态、页面 URL 或普通列表。完整连接配置仅管理员显式生成/查看/复制，不把含密码的配置串写进提示消息。

提供握手超时、未认证并发限制、认证失败限速、用户/入口连接及 UDP 关联上限、报文长度约束、有界队列与来源访问规则。认证不能防带宽型 DDoS，不以频繁失败触发无界地址表或误封整片 NAT 用户。

## 7. 配置模型、主备使用和兼容

### 入口与出口

- go_web：新增独立入口集合，包含 ID、名称、账户 ID、`hysteria2` 或 `mieru` 协议、监听地址、认证、HY2 身份引用、资源限制；Mieru 外层明确为 TCP。多个入口共享账户 Engine 租约，不复制 token。
- go_web 出站：增加 HY2 与 Mieru 类型上游参数，保持原 `upstream` SOCKS URL 合同，不把协议认证字段混进 ET 账户 token。
- mcbeproxy：扩展已有代理端口类型为 HY2/Mieru，复用所选出站、用户、来源 ACL 与目标路由；出站侧补齐实际路径和可信身份导入，不重复实现完整内核。
- 旧配置缺少新增集合时为空，不自动启用、换端口、安装证书或轮换密码。默认推荐 HY2 只作用于新建安全代理。

### 主备切换

第一版明确提供“HY2 主力”和“Mieru TCP 兼容”两份可选配置，**不默认静默自动回退**。管理员可按网络条件选择；协议切换只作用于新建业务流，已有流保持原 owner。

不把认证失败、证书不匹配或目标拒绝归类为“UDP 不通”并转走其他协议。后续若增加自动选择，应单独设计探测、错误分类、冷却、信任及可观测规则；不能通过活跃业务请求竞速、双发或迁移来冒充无损切线。

不支持的链式组合明确报错，不能因外层 UDP 不可用而偷偷本机直连或绕过指定出口。

## 8. 低延迟实现约束与失败边界

### HY2 主力调优

- 默认采用锁定版本已支持的自适应拥塞控制，优先评估 BBR；禁止按虚高带宽强推 aggressive/Brutal 来宣称低延迟。
- 不盲目放大 QUIC 窗口或发送队列。每关联有界排队、限长数据报、缓冲复用，不为每包新增 goroutine。
- 游戏数据报不套额外可靠流/ARQ。QUIC 本身仍有拥塞控制，丢包和竞争仍可能延迟发送，不承诺零抖动。
- 同一共享 QUIC 连接上的流不互相等待 TCP 字节序，但仍共享拥塞资源；防止大下载/资源包挤占其他玩家须纳入并发验收，不未经测试承诺绝对隔离。
- MTU/路径发现与库配置配套；超长 UDP 按标准 HY2 分片或丢弃，有界重组和过期清理，不等待缺失分片无限增长。
- 共享客户端按明确的入口/身份/路由配置持有并复用，限制冷握手并发；不能每个游戏包或面板轮询新建 QUIC。

### 所有 owner 的生命周期

逐包拥塞/队列满只影响当前报文，不关闭共享 ET/HY2 会话、不更换原游戏关联源端口。单流取消不能关闭其他玩家共享的会话；最后一个租约释放才收尾。

真实会话死亡唤醒所有依赖流并取消拨号，晚到连接关闭，死缓存不复活。旧流回收精确核对不可变所有者/ID，不能按地址或名字误删新连接。

空闲以双向业务活动为准，协议心跳不伪造业务流量/时长。支持半关闭、停机、拨号取消，避免后台协程和密钥/缓冲泄漏。

普通保存不因无关字段变化重建监听；需要重建的协议/地址/主密钥/身份变更遇活动连接时明确拒绝或等待管理员选择维护操作。停用/强制关闭必须由管理员显式触发。

真正断网或 ET 重授权仍可能打断应用连接；不承诺换协议/换 conv 后旧游戏会话无损。

## 9. 两段链路与性能验收

HY2 解决的是两程序之间的传输语义，不改变之后 ET 内部已有的重传、排队和出口质量。

例如 `MCBE → HY2 数据报 → go_web → ET → 游戏服`，前段避免外层 TCP 队头阻塞，不代表 ET 后段没有 ARQ 或拥塞。必须分别记录前段、ET 后段和总结果，不能把全链路延迟归为入口协议。

### 默认主力的验收资格

HY2 是机制上推荐的默认候选，不是已经证明所有线路最快。正式发布前在相同机器/目标/出口与流量条件下对比：已有 SOCKS5、HY2、Mieru TCP；可将已有 SS2022/TUIC 客户端作为独立基线，不因此扩展本期入口范围。

记录冷握手、暖连接 RTT p50/p95、抖动、应用丢包/超时率、排队丢包、吞吐、CPU、内存和 goroutine 趋势。最低要求是结果可复测，并发下载/资源包不能导致其他玩家或共享引擎被错误关闭；不编造固定毫秒提升。

在受控本地环境覆盖低延迟、长RTT、随机/突发丢包、重排、MTU受限及慢消费者。若实测某环境不适合HY2，在界面保留选型提示，不为保持推荐名称而掩盖退化或改造测试。

真实 ET 账户、第三方 MCBE 登录、资源包、同 NAT 多玩家、重连和长时稳定性单独验收；需明确授权后进行，不能以本地 echo/Pong 或编译代替。

## 10. 管理体验

沿用两项目 Vue/Naive UI、现有权限与小号响应式组件，不另引入界面框架。

- 新建入口默认推荐“HY2 · UDP网络主力”；备选为“Mieru TCP · 受限网络兼容”，两者均写明“支持业务 TCP+UDP”。
- 分开显示入口监听状态、外层协议、认证/信任、出站 Engine 状态和目标测试，不能以 ET ready 冒充入口正常。
- HY2 提供“自动生成服务身份”和可信连接配置导入/导出，默认无需域名、证书路径手填；高级选项才开放自备证书。
- Mieru 仅需入口 IP/端口、用户名/密码及必要的资源限制，不显示不相关证书字段。
- 自动识别本机监听接口不等于检测公网 NAT；客户端实际可达地址允许手工覆盖，无隐藏外网请求。
- 日志分层：监听失败、认证拒绝、身份不可信/过期、外层 UDP 不可达、上游/ET 不就绪、目标拒绝、逐包拥塞、空闲回收和真实会话死亡。

## 11. 依赖、实现边界和许可证

优先使用 HY2 官方 core 与 Mieru 官方 Go API，适配各项目已有 Engine/代理端口/路由 owner。mcbeproxy 已有相关依赖不等于 go_web 已能使用或两项目服务端已实现。

实施前核对具体锁定版本、安全公告与跨版本互操作；官方应用版号与 core 模块版号分别列明，不借本期批量升级 Mihomo/Xray。Mieru GPL 等依赖许可及分发义务必须审查；可嵌入API不等于无许可证约束。

不默认塞进完整 sing-box/Mihomo 主程序或额外常驻代理；不 fork 协议加密/QUIC/重传栈，不修改模块缓存，不用两个工程之间临时相对路径导入代替清晰依赖。

若共享适配代码能确实减少维护，应在逐文件计划单列模块与版本边界，不先造庞大插件框架。

## 12. 必须覆盖的本地合同

1. 两协议 × 两项目双向角色的真实协议 TCP/UDP 往返；分别与标准实现样例互操作，不能只验证两份相同错误的封装。
2. HY2：TCP流和UDP数据报同时工作；认证前无目标连接；丢包不因可靠交付游戏旧报文而阻塞后续完整数据报；分片超时、限流、MTU和资源上限有边界。
3. 身份：自动生成仅一次、重启复用；不可信证书/错误指纹/错误服务名/过期证书失败；管理员正确导入后成功；轮换不静默信任。
4. Mieru：外层只TCP；业务UDP保留边界；错误用户名密码、时间异常和畸形帧安全失败；不创建客户端可见随机UDP入口。
5. 路由：go_web认证请求真正走受控Engine/ET租约，mcbeproxy遵守所选出口和ACL；不支持的代理链不直发绕过。
6. 生命周期：同NAT多用户、旧流晚清理、单流拥塞/取消、队列满、共享会话死亡、停机晚到拨号、双向空闲、设置更新和资源释放。
7. 配置：旧记录不迁移，新增字段API往返，新建推荐与旧节点保持分别验证；公开数据无秘密。
8. 界面：字段显示/校验、服务身份导入/到期提示、承载文案、权限和手机布局；构建到临时目录，不覆盖正式产物。

## 13. 首期范围与后续交付

首期只推进 **HY2 主力 + Mieru TCP 兼容** 的两项目入口/出口与以上验收；现有其他协议保留，不新增 SS2022/Trojan/AnyTLS/TUIC/VMess/mKCP/WireGuard 入口，不自造线协议，不做自动打洞、ACME和静默跨协议迁移。

设计与逐文件计划、sing-quic 服务端调整均已获得批准。当前已实现两项目双角色、版本一可信配置、管理员管理接线及本地测试；证书只在显式创建时生成，测试身份位于临时目录。

本地验收：HY2 / Mieru 两方向的 TCP 和 17/1400/4000 字节 UDP 往返通过；身份重启复用、错误服务名/摘要、错误密码、用户禁 UDP、出口归属、活动变更保护和停机等已运行的合同分别验证。两模块构建与两端临时前端构建通过；临时产物清理，未部署、重启或提交。

已知实现边界：锁定 HY2 core 的4096字节组包缓冲包含地址头，超限负载明确报错，不宣称支持65507字节。HY2/Mieru 已支持逐跳叠加；HY2 链式后跳当前使用固定端口，端口跳跃因前跳多目标 UDP 合同未完整接入而明确拒绝。显式 SOCKS5 链的数据面也强制经过前跳，不再探测后直发绕链。

本地链式验收：HY2→HY2、Mieru→HY2、HY2→Mieru、Mieru→Mieru及 Mieru→HY2→Mieru 的 TCP/UDP 往返、关闭收尾通过；SOCKS5→HY2、SOCKS5→Mieru、HTTP→Mieru 通过；仅 TCP 前跳或禁 UDP 用户不能承载后跳 HY2，不回退直连。链编辑器增加承载警告。并非所有其他协议组合都已实测。

证书显式轮换/到期预警的完整管理体验、全部资源/畸形帧边界、受控丢包性能与真实 ET/MCBE 长时验收仍需逐项完成；基础互操作通过不代表第12节所有条目已全部验收。
